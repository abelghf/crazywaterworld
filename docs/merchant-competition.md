# 海商王竞争与交易节奏

2026-11-26：这次调整保留冲刺整期220根、每日100根、每程4根的上限。达到5000万后停针，继续自然走商，不自动购买指南针。额度是上限，不是达标所需针数或保证。

## 执行行为

- 新默认值及重新套用的三个预设采用10秒港口监控。旧账号已经保存的间隔保留。
- 刷新、到港和已知港口的公开航程变化会唤醒现有串行检查。确认买卖或升级后，下一秒安排重新核价、重算；实际间隔还包含请求和账号排队耗时。
- 下一笔仍要经过状态、价格、库存、开关和消费记录复核。未知结果只恢复原票据，不并发或重复发单。
- 规划不再强制每笔至少60秒。首次参考监控配置，随后使用最近32次检查耗时与排队延迟的P90，并单独保留成功交易的耗时样本。历史 `actionSeconds` 是规划估计，不是实测成交间隔。

## 选港与指针

### 每日收市（2026-11-26）

`merchant.closeBeforeRest` 对应共用开关「收市前加速与跨日接续」，默认开启，受使用指南针总开关约束，适用于全部九种用针模式。它在配置的当天最后一轮开市内刷新后先检查收市机会，再执行所选模式的原有逻辑。`dailyClose` 仍可选，名称改为「仅收市用针」，方便只在收市阶段加速的用户。关闭共用开关不关闭另设的最后一根防抢，也不取消其他策略原有的末日收尾。收市判断不硬编码20:00/22:00，活动提前结束会截短实际收盘。

在途先按“加速确认＋逐批出售＋可能升船”枚举保住当日成交的最少用针数。普通交易日若为隔夜接续额外用针，还须以本轮有效的目的港亲访报价核对卖货回款、余舱、现货、同港先到同行的潜在耗库和具体采购销港；所有采购与出航须赶在收盘、刷新及报价有效期之前，且自然航行能在次日开市前抵港。到港仍重新核价、核库存，不承诺次日售价和收益。

自然到港也能备货出航、赶上同一次开市时，不把单纯早到算成多一趟；自然到港时的报价可能过期也不能作为它必然买不到的证据。缺少有效现货依据时，只为当日卖货补足针数；若这些针已经留出了余量，可预留采购时间，但不为假设中的下一船多花针。来不及备货出航但还能卖货时允许只抢救当日成交，不据此再开一条依赖隔夜备货的新加速航线。

同港抢先模式即使没有同行，也先检查这项收市补救；每刷新最多一程模式仅对已核对针数、利润和时限的额外收盘航次放开一次一程限制。免费针模式仍只使用本期已核实的免费余额，不借用旧库存、不自动补购。配置版本75升级到76时仅为缺项补上开启值，显式关闭保留，所选模式、总开关和各项预算不改动。

另行开启的“最后一根防抢”继续生效，独立收市模式也不取消该显式开关；预算与达标停针仍共同约束。

本次通过收市时序、次日清舱、末日及额度边界的离线用例，并覆盖实际交易执行入口、设置HTTP保存和配置页回读。下文312局清仓对照的决策基线不包含这次新增收市规则，不能将其达标比例解释为新规则的整期收益预测。

到港后先按本港实价处理可售异地货，再用实际回款和当前库存决定下一程。普通交易日的末轮采购另留出航时间；明确标记为隔夜的船自然到达，次日重读行情并沿用原隔夜清舱流程。来源港货物和超过原亏损限制的货物仍可能留仓，因此“收市清仓”不保证所有货都能出售。

末日以是否还存在下一次实际开市判断，即使活动在次日凌晨才结束，也不安排隔夜采购或预留隔夜动作；仍可在既有停止采购窗口、已核实针数和实际收盘时限内完成当天盈利航次。原有“距活动结束停止采购”及亏损配置口径保持不变。每日、每程、整期额度、保留量、达标停针和未知结果防重全部继续生效，发送前重新核对流程余量。

### 采购与竞争

采购组合与本程销港一起决定，普通采购和隔夜备货均排除销港的已知特产。后续补货、出航或寻价时，本港买入的货物继续约束候选港；只能改去与这些货物兼容的港口，无兼容销港时等待。此约束来自当前持仓的商品与来源港，重启不会丢失，也不把某个旧目的港永久锁死。

隔夜按每个候选销港分别生成采购组合，宁可少装也不把互相需要不同销港的货混装。特产情报未知时不新增隔夜采购。以前航次留下的滞销货可以继续占舱，不阻止其他批次出售；普通航线不把销港特产计入预计出售利润、回款和释放舱位，计划显示留仓数量。到港后有实际盈利的旧货仍可出售，既有隔夜货开市清舱规则保留。

比较下一程采购机会时，按同盟、同港、同一刷新轮次筛选先到船，使用船级容量估计特产可能被买走的数量。去别港、晚于本船采购或消耗上轮库存的船不扣当前机会。未知船级采用最大船容量的压力情景；对手资金、舱位占用、停港等待和实际采购意图仍不可见，因此不把估计写成确定库存。

目标类用针策略（达标优先、前期省针、仅用本期免费针）比较1～4根指针带来的采购增益。支持两种依据：

1. 本轮有效期内亲访报价，加上公开同港船容量，比较早到与晚到的可采购组合。只对特产估计耗库，不给每种商品各扣一整船。
2. 本期同港、同一历史刷新轮次、同次停港的两份库存记录。价格必须一致，扣除自己的采购量，替代商品也参与配货。

同行按到港即可采购处理。本船的计划买卖仍预留实际执行时间。赶不上最早同行、库存足够或缺少可比证据时，不因抢货额外用针；升级回款、目标航次和收尾判断仍然保留。有具体抢货增益或已确认的紧急收尾航次时，可以越过12港/15:00情报门槛。普通升船不能仅因存在同向船就绕过门槛。

达标优先模式下，空船、本港特产售罄、没有值得执行的盈利航线且补货在“刷新前最多等待”范围内时留港；该参数默认120秒，0关闭。不再把模拟中的“提前5分钟清舱、刷新后20分钟统一用针”当成通用规则。

## 离线模拟与复跑

工具 `tools/merchant-competition-sim.mjs` 复用生产决策层，用17港共享有限库存、同盟船、资金、船级及针预算按事件时间推进。输入必须是用户自行导出的四天行情与到账记录，原始账号数据不进入仓库。

```powershell
$env:MC_RIVALS = '30'
$env:MC_VARIANTS = 'baseline'
$env:MC_DISTRIBUTION = 'mixed'
$env:MC_SELF_STEP = '2'
$env:MC_POLL_SECONDS = '10'
node tools/merchant-competition-sim.mjs <行情.json> 6 <到账记录.json> 5001 sprint 169 v70
```

示例169根开局库存对应该研究样本后续实领51根，并非通用免费额度。`MC_CAP` 默认220。`MC_SELF_STEP` 是假设的每笔操作耗时，`MC_POLL_SECONDS` 是无动作时的检查周期；2秒仅用于敏感性测试，不表示线上必能达到。同行默认操作约30秒，公开信息只来自已发生的航程，不能读取其未来采购。

分布可选 `greedy`（逐利集中加速）、`diverse`（近似收益港分散）、`staggered`（错峰）、`mixed`（同时分散与错峰）。批处理工具 `tools/run-merchant-competition.mjs <jobs.json> <输出目录> 4` 支持每项指定 `input`、`rewards`、`initialPins`、`engineRoot`、`engine`、`rivals`、`selfStep`、`pollSeconds`、`distribution`、`seeds`、`firstSeed`、`variants`。输出目录应使用新目录，保留每批JSONL及stderr。比较旧版可令 `engineRoot` 指向旧版独立检出目录，保持同一输入和种子。

`python -X utf8 tools/summarize-merchant-adjustment.py <旧版结果目录> <新版结果目录>` 汇总完整结果；stderr非空或同场景种子重复会报错。逐笔检查包括资金、舱位、库存守恒和针数额度。结果用于比较假设，不能解释成真实同盟达标概率。

## 清仓换货实验（2026-11-26）

实验基于 `e22ce4b` 的采购销港约束，生产策略保持不变。`tools/merchant-clearance-policy.mjs` 只由离线模拟调用，不连接游戏、不修改账号的亏损上限。以相同行情种子、同行起点、针数和执行速度比较四组：

- `baseline`：当前生产策略，按整船销路选择出售或持有，保留已有隔夜清仓规则。
- `sellFirst`：在当前规则之外优先卖完盈利或保本的异地货，不额外亏损出售。
- `clearAll`：优先卖完所有允许在本港出售的货，包括亏损货。
- `opportunity`：用本港实际回款试算清仓后可采购的组合；扣除清仓耗时和公开先到船的潜在耗库，只有下一程预计累计利润进度比当前方案高至少10%，且现货、本金及交易时间够用，才逐批换仓。每次实际成交后重新判断，不能保证之前预测的组合仍可买到。

后三组仅在累计利润未达5000万时启用，达到后恢复原策略。不允许出售来源港货物，也不把亏损直接从累计利润扣除。现金按真实盈亏变化，检查 `累计利润－已实现亏损＝现金净收益`，以及现金、持货成本、库存和针预算的守恒。最低本金与回撤按“现金＋未售货物进货成本”计算，属于账面周转规模，不是当前可全部变现的金额。

主比较预先固定种子7001～7012、0/15/30艘同行、17港分散选港并错峰加速、本船操作10秒及检查10秒；敏感性组使用种子7001～7006，分别测试0/30艘同行下的2秒操作，以及30艘同行集中选港的10秒操作。每种条件配对四个策略，共54组、216局。所有组均为初始1万商会币、169根针加样本中实领的51根，整期上限220根，假设解锁后的钻石升船可执行。

主分档出现全部达标后，追加30艘分散同行、10秒操作、同一批12个种子的180根预算压力组；该组全部未达标，再补200根中间预算。两次补测只改变本人整期用针上限，背包初始针数与到账、对手的220根上限、行情和清仓规则不变，各48局。补测是探索性的预算敏感性检查，不是新增独立行情，也没有据结果调整10%的换仓门槛。

本次每笔采购保留独立批次，清仓时间逐笔计算，不与上文旧版合并批次的结果直接比较。运行前固定决策代码及模拟器哈希；完整结果和逐笔反例保存在本地 `output/merchant-clearance-20261126/`。合成行情来自102份历史快照的分类抽样，仍不是未来价格预测或真实达标概率。

复跑时在批处理任务中设置 `variants: ["baseline", "sellFirst", "clearAll", "opportunity"]`，其余输入沿用前述命令。使用 `python -X utf8 tools/summarize-merchant-clearance.py <jobs.json> <结果目录>` 核对批次完整性、相同种子配对和资金口径，再汇总达标、针数、实际换仓次数及盈亏。实验规则的人工边界用例由 `node tools/selftest-merchant-clearance-sim.mjs` 验证。

220根上限的216局中，四组各有52/54局达标。0/15/30艘分散同行的10秒主组均为12/12；两组2秒操作均为6/6；30艘集中选港的10秒组均为4/6。没有任何清仓策略把原先未达标的样本救到5000万，也没有把原先达标的样本降到目标以下。多数样本没有触发额外出售，不能把相同结果当成策略优越性证据。

逐个相同场景比较整期累计利润：优先卖盈利货是2组增加、45组相同、7组减少；无条件清仓是4组增加、42组相同、8组减少；有条件换仓是3组增加、48组相同、3组减少。220根组额外亏损换仓只在无条件策略发生5笔、有条件策略发生3笔，触发数量很少。

一个可逐笔复查的反例是种子7008、无同行、10秒操作。有条件策略以7000亏损释放一批旧货，试算下一程利润从392495提高到793500，实际下一程赚1362750。但原策略把旧货继续运到另一港盈利出售，后续路线也随之不同：整期累计利润为63605188，有条件换仓为61636847，少1968341；两组都用191根针，达标时刻相同。该例说明局部换货成功不等于整期目标更优，不能把全部差异归因于7000的本金损失。

180根组四种策略的整期利润中位数依次为44270894、44124780、44124780、44270894；200根组依次为49165075、49104708.5、49054790、49165075，两档的用针中位数均达到各自上限。200根组中，无条件清仓让两个原本达标的样本未达标，优先卖盈利货影响其中一个，有条件换仓未改变达标样本。所有预算与竞争条件下，三种额外清仓策略都没有救回任何当前策略未达标的配对样本。

200根的种子7005最直接体现亏损清仓的代价：当前策略累计50047292，无条件清仓累计49826722，二者均用200根；后者额外清仓一次、亏损31500。种子7007即使没有亏损，提前卖货也使累计利润从50491497变成49926559，说明机会成本还包括原货在其他港的利润及后续航线变化，不能只看现金损失。

结论：亏损不倒扣累计利润这一前提已在模拟记账中落实，但本次结果不支持默认到港全仓清仓，也不支持仅凭下一程预计进度提高10%就启用亏损换货。维持现有生产策略和亏损设置；有条件换仓只保留为实验，不接入真实交易。这不能证明所有择机换仓方法都无效，尤其亏损换仓触发较少；如继续研究，应同时比较持有旧货的后续收益、换仓后的多程收益、实际库存、回款与交易耗时，而不是只增加单程利润阈值。
